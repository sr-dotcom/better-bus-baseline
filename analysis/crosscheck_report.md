## How gtfs-kit defines a value differently

- **Headway window ends.** gtfs-kit keeps a trip start `s` when `headway_start_time <= s <= headway_end_time`, so a trip at exactly the end time counts. The marts are half-open, `start <= s < end`. The first AM-peak run below uses the window as asked, 06:00:00 to 09:00:00. Whole-second times make `<= 08:59:59` the same set as `< 09:00:00`, so every scored comparison also runs with the end set to one second earlier, which is the marts' window.
- **Headway unit.** gtfs-kit returns minutes as a float (`max_headway`); the marts hold seconds. The cross-check divides the mart seconds by 60 and accepts a difference under 1e-9 minutes.
- **Which stop a trip is measured at.** Both take the stop_times row with the lowest `stop_sequence` as the trip start and use its `departure_time`. gtfs-kit sorts `stop_sequence` as an integer; the marts cast it to an integer in staging.
- **End time.** gtfs-kit `end_time` is the `departure_time` of the last stop. The span mart uses the `arrival_time` of the last stop (`last_arrival_s`), which is what the sheet defines. The report compares gtfs-kit `end_time` with both the mart value and the last-stop departure; where the two differ, the gap is the dwell time at the last stop. The table above shows whether any trip does.
- **Zero-length trips.** gtfs-kit drops trips whose duration is 0 or less (`end_time - start_time`, last-stop departure minus first-stop departure) before it counts trips or measures start, end and headway. The marts keep every active trip. The report counts trips both ways.
- **Which trips run on a date.** gtfs-kit uses its own calendar code on `calendar_dates.txt`. The marts use the `service_id` rule in `sql/intermediate/40_active_trips.sql` (an exception_type 1 row and no exception_type 2 row). Both feeds hold type 1 rows only. The trip-count rows in the table above show whether the two pick the same trips.
- **Direction split.** gtfs-kit `split_directions=True` groups by `direction_id`. Route start and end in `route_span` cover both directions, so the route-level check takes the earliest start and the latest end over the two gtfs-kit directions.
